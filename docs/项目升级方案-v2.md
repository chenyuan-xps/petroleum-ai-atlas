# 项目升级方案 V2 · 从案例库到智能决策实验平台

> 状态：待确认，尚未实施  
> 目标：在保留现有六个案例、hash 路由、案例上传机制和纯前端离线运行的前提下，把网站升级为“统一视觉系统 + 数据驾驶舱 + 智能决策交互 + 可视化叙事”的平台。

- 5 类 AI 方法：CV 16、TS 26、NLP 4、OPT 25、KG 4；

### 1.2 与“高分平台”的差距

| 差距 | 当前表现 | 升级方向 |
|---|---|---|
| 首页故事 | 更像目录页，先讲“有什么” | 先讲“解决什么问题、AI 放在哪、我完成了什么” |
| 个人任务 | 学号 07 与完井 4/4 没有成为主叙事 | 增加任务完成度驾驶舱，直接对应答辩要求 |

| 视觉统一 | 案例内部已经统一，但平台层与案例层仍像两套 | 统一状态色、指标卡、可信度条、决策链、结论区 |
| D3 架构 | 各案例各自绘图，重复代码多 | 建立共享 `IQViz` 可视化组件层，案例做组合 |
| 决策叙事 | 以“数据→图表→结果”为主 | 展示“工程对象→数据→模型→风险→推荐→人工复核” |
| 案例差异 | 六个案例交互深度不完全一致 | co1/co2/co4 做深度交互，co3/e1/pr2 做中深度增强 |
| 平台功能 | 有方法反查、案例库，但缺搜索与对比 | 全局搜索、案例对比、项目说明页 |
| 工程边界 | 有合成数据声明，但未形成统一模块 | 每个案例统一展示数据可信度、模型边界、人工复核 |

## 2. 升级定位与设计原则

### 2.1 新定位

> 一个面向石油勘探开发全流程的智能化场景地图，以完井阶段为重点，通过 D3.js 把工程对象、数据分析、模型预测、风险评估和智能决策串联成可操作的实验平台。

对外名称建议：

- 主标题：**石油勘探开发的智能化可能性地图**
- 副标题：**UPSTREAM INTELLIGENCE ATLAS**
- 平台名：**油气井完井智能决策实验室**
- 首页主张：**从地质勘察到采油，把 AI 放进每一条工程决策链**

### 2.2 设计原则

1. **不推翻重写**：保留现有 hash 路由、案例注册契约、上传机制、六个案例包。
2. **渐进增强**：新字段全部可选，旧案例和上传案例仍能正常渲染。
3. **平台层与案例层分离**：平台负责导航、统计、叙事、可信度；案例负责专业模型与交互。
4. **统一但不抹平**：共用视觉语言与 D3 组件，但保留每个案例的工程对象特征。
5. **先故事后图表**：每屏先回答“为什么”，再展示“是什么”，最后给“怎么做”。
6. **纯前端离线**：不引入后端、CDN、外部 API、登录依赖。
7. **可验收**：每批交付都做构建、无头浏览器、上传与打包回归。

## 7. D3 可视化组件层

### 7.1 架构选择

不把 D3 拆成十几个细碎文件，避免案例包依赖过多；采用**一个共享组件文件 + 按领域分组**：

```text
assets/cases/iq-viz.js          # 源码，暴露 window.IQViz
assets/cases/iq-viz.css         # 可选，组件样式（并入 iq-demo.css 也可）
```

构建时复制为每个案例包的：

```text
<case>/demo/iq-viz.js
```

案例包文件从 5 个变为 6 个：

```text
case.json
demo/index.html
demo/demo.css
demo/demo.js
demo/iq-viz.js
demo/d3.v7.min.js
```

> 这是一次契约扩展，需同步更新构建脚本、打包脚本、上传校验、模板与文档。旧 5 文件案例仍兼容。

### 7.2 组件 API 草案

```js
IQViz.theme(d3)                 // 统一颜色、字体、轴样式
IQViz.tooltip(container)        // 统一悬停提示
IQViz.responsive(svg, draw)     // viewBox + ResizeObserver

IQViz.chain(el, stages, opts)           // 13 阶段作业链
IQViz.methodBars(el, methods, opts)     // 方法分布
IQViz.matrix(el, stages, methods, opts) // 阶段×方法热力矩阵
IQViz.radar(el, axes, series, opts)     // 雷达图
IQViz.heatmap(el, grid, opts)           // 参数空间热力图
IQViz.contours(el, grid, opts)          // 风险等高线
IQViz.series(el, series, opts)          // 折线/面积/区间
IQViz.riskBand(el, value, thresholds)   // 安全区/风险带
IQViz.wellbore(el, layers, opts)        // 井筒/地层/滑套
IQViz.workflow(el, steps, opts)         // 决策链路/流程
IQViz.compare(el, groups, opts)         // 前后对比
IQViz.concept(el, nodes, links, opts)   // 概念图
```

### 7.3 实施策略

不强行重写六个案例的全部绘图，采用“三段式”：

1. **先建组件层**：主题、提示、响应式、系列、雷达、热力、等高线、对比；
2. **三个试点**：co1 雷达、co2 热力/等高线、pr2 时序/区间改用组件；
3. **其余增强**：co3、co4、e1 新增部分优先用组件，原有稳定的专用绘图保留。

这样既有组件化架构，又避免为了“统一”把已经稳定的案例改坏。

## 13. 风险与控制

| 风险 | 影响 | 控制 |
|---|---|---|
| 左栏改造影响现有导航与吸顶 Tab | 路由正常但布局错位 | 先做外壳，单独验证 4 个断点 |
| 组件化重写案例导致回归 | 已通过示范被改坏 | 先试点 3 个，保留专用绘图 |
| 新字段破坏上传兼容 | 旧案例包无法导入 | 字段全可选，校验只警告 |
| 案例包新增 `iq-viz.js` | 打包清单遗漏 | 构建、打包、上传三处同步 |
| 动画过多影响性能 | 滑块卡顿 | 滑块重绘去抖，动画可暂停，尊重 reduced-motion |
| 视觉升级过度 | 破坏原有专业气质 | 保留暖白/青玉/陶土，不做暗色大屏 |
| 范围过大 | 交付周期拉长 | 分三批，每批独立验收 |

### 非目标

- 不接真实油田数据；
- 不做后端、数据库、登录；
- 不引入 Vue/React 或图表库；
- 不替换现有六个案例的专业模型；
- 不做视频自动生成；
- 不承诺工程结论可直接用于现场。
